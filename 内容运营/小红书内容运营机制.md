# 小红书内容运营机制

## 1. 功能定位

把表达资产转化成内部推送和外部内容。

内部目标：

- 用推荐式推送反哺用户认知。
- 把复盘变成持续学习。
- 把表达共创沉淀成思考卡片。

外部目标：

- 运营一个小红书账号，持续输出高价值表达内容。
- 帮助同样需要组织场沟通和关系场调频的人。
- 把表达系统从个人使用工具，延展成公开内容资产。

## 2. 内容输入来源

输入来源：

- 线程资产：每个对话中沉淀的典型场景、表达策略和案例。
- 主体结构：已经验证过、可复用的判断原则、表达规则、表达结构、场景方案和风格模式。
- 外部反馈：用户对推送、小红书内容、表达风格和选题方向的反馈。

## 3. 内容触发机制

内容由每日增量复盘触发。

每日增量复盘负责判断：

- 是否有新增线程资产。
- 是否有主体结构更新。
- 是否有新的内部表达资产值得推送。
- 是否有内部表达资产适合转化为外部内容资产。
- 是否有外部反馈需要反哺主体系统。

## 4. 内容资产颗粒度

内容资产颗粒沿用 [表达系统公共模块](../表达系统公共模块.md#3-资产沉淀模型)。

本文件只维护外部内容资产的运营方式：内容选题、推送卡片和发布稿。

每条内容必须标注来源颗粒，避免统称“认知”“技巧”或“方法论”。

## 5. 推荐式推送逻辑

基于增量和价值推荐。

优先推送以下内容：

- 最近频繁出现的沟通任务或场景方案。
- 用户刚刚经历过、短期内可能复用的表达规则。
- 能显著提升表达判断力的判断原则。
- 可以从内部案例抽象出来、但不暴露敏感信息的表达结构或风格模式。
- 适合转化成小红书选题的外部内容资产。

不推送以下内容：

- 没有新增表达资产的历史重复总结。
- 只适合私下使用、不可公开化的具体业务细节。
- 缺少普适性的单次话术。
- 过度鸡汤、缺少方法和样例的观点。

## 6. 单条推送结构

每条推送包含：

- 标题：一个明确、有场景感的问题或判断。
- 资产颗粒：判断原则 / 表达规则 / 表达结构 / 场景方案 / 风格模式 / 内容选题 / 推送卡片 / 发布稿。
- 场景：这条内容适用于什么表达情境。
- 核心观点：这次要反哺的表达判断是什么。
- 方法拆解：为什么要这样表达，背后的结构是什么。
- 示例话术：给一段可直接参考的表达。
- 可复用规则：下次遇到类似场景怎么迁移。
- 小红书化标题备选：2-3 个更适合公开发布的标题。

## 7. 小红书内容风格

小红书风格：

- 标题有钩子，但不夸张。
- 开头点中具体表达痛点。
- 内容短、密度高、能直接拿走用。
- 有场景、有反差、有方法、有例子。
- 语气像一个经历过互联网职场的人在真诚分享。
- 避免泄露公司、业务、人物、数据等敏感信息。

## 8. 内容栏目

初始栏目：

组织场表达栏目：

- 组织场表达拆解：拆一句话为什么这样说。
- 向上汇报模板：Leader 沟通、阶段同步、风险暴露。
- 季度会表达：Highlight、Lowlight、OKR、规划。
- 高阶表达升级：从“做了什么”升级成“产生什么结果”。
- 反馈边界话术：拒绝、提醒、反馈、表达立场和边界。
- 职场定义权：围绕“你不定义，就被定义”的认知系列。

关系场表达栏目：

- 关系调频：围绕亲疏、情绪、期待和边界的表达判断。
- 社交破冰：认识、开启话题、自然靠近。
- 真诚表达：喜欢、感谢、歉意、委屈和不满如何说。
- 低压力推进：邀约、试探、确认关系、提出期待。
- 温柔边界：拒绝、降温、拉开距离和体面退出。
- 冲突修复：误会、尴尬、伤害后的解释和降温。

## 9. 内容资产管理

运营内容单独沉淀到：

内容运营/

建议命名：

YYYY-MM-DD-主题.md

每个内容资产包含：

- 来源线程
- 资产颗粒
- 适用场景
- 内部认知推送版
- 小红书发布版
- 标题备选
- 可公开程度
- 是否已发布

## 10. 和主系统的关系

分工：

- 表达操作系统：沉淀方法。
- 小红书内容运营机制：转化内容。

- 内部推送。
- 外部发布。

两者互相反哺：

- 表达共创产生内部表达资产。
- 内部表达资产生成内容选题、推送卡片和发布稿。
- 内容发布后的反馈再反哺场景库、策略库和风格库。
