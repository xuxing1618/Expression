# 系统设计线程

## 线程主题

表达项目定义与系统设计

## 线程 ID

系统设计主线程。

## 场景识别

- 沟通任务：对齐决策 / 推进协作
- 对象：用户本人 / 后续项目共创会话
- 媒介：项目文档 / 对话沉淀
- 压力：低压力
- 风格：建筑师式 / 金字塔原理式

说明：

本线程用于定义系统的问题空间、模块关系、资产颗粒度和迭代方式。

## 用户目标

把单次组织场表达润色能力，组织成一套可持续迭代的组织场景表达系统。

## 沉淀内容

- 项目名：表达
- 项目定位：面向组织场的表达优化系统
- 底层哲思：组织场是一个高密度的定义与被定义的场域。你不定义，就被定义。
- 产品主张：在关键组织场景里，主动定义问题、定义贡献、定义诉求、定义边界，也定义自己。
- 前台主流程：输入承接、场景识别、表达策略、语言生成与润色
- 后台迭代流程：沉淀层、反哺层
- 操作系统调用机制：表达优化类请求需要默认进入前台主流程，并通过输出前自检保证执行稳定。
- 轻量模式最小结构标记：即使压缩过程说明，也要保留“场景判断 + 表达策略”两行，保证系统执行痕迹稳定可见。
- 场景判断受控词表：沟通任务必须优先使用六个标准任务名，避免自由命名导致场景库失控。
- 场景识别结构升级：一级场景从“汇报 / 对齐 / 争取资源 / 解释问题 / 推进协作 / 敏感沟通”调整为“汇报同步 / 对齐决策 / 争取支持 / 解释复盘 / 推进协作 / 反馈边界”。敏感沟通不再作为一级场景，而是下沉为压力修饰因子。
- 结构偏好：建筑师风格；先审结构，再讲结构。

## 资产颗粒归类

- 判断原则：结构设计要先定义问题空间，再解释方案结构如何支撑问题空间。
- 表达结构：问题空间 -> 设计目标 -> 模块划分 -> 模块关系 -> MECE 检查 -> 适用边界。
- 风格模式：建筑师式说明，强调结构自洽、边界清楚、支撑关系明确。
- 判断原则：金字塔原理作为表达呈现工具箱，用于保证结构的上下支撑关系、同层分类边界和表达顺序。
- 表达结构：组织场景识别 = 沟通任务 + 对象 + 媒介 + 压力 + 风格。
- 表达结构：前台主流程 = 输入承接 -> 场景识别 -> 表达策略 -> 语言生成与润色。
- 表达结构：后台迭代流程 = 沉淀层 -> 反哺层。
- 表达规则：轻量表达优化可以压缩过程说明，但不能跳过底层的场景识别和表达策略判断。
- 表达规则：轻量模式至少输出“场景判断：沟通任务 + 对象 + 媒介 + 压力 + 风格”和“表达策略：一句话说明取舍逻辑”。
- 表达规则：场景判断里的沟通任务优先使用“汇报同步 / 对齐决策 / 争取支持 / 解释复盘 / 推进协作 / 反馈边界”，多任务场景可组合标准任务名。
- 判断原则：系统执行不稳定通常不是缺少理念，而是缺少触发条件、执行步骤和输出前自检。
- 判断原则：敏感性不是一级沟通任务，而是可叠加到不同任务上的压力属性。

## 可复用规则

- 不把表达优化理解成单句润色，而要放回组织语境、对象关系和沟通目标中判断。
- 每次生成表达前，先判断用户要完成的沟通任务，再叠加对象、媒介、压力和风格修饰因子。
- 输出时既要给最终话术，也要沉淀背后的表达策略。
- 重要输出要解释为什么这样表达，让用户知其然，也知其所以然。
- 表达优化请求默认触发表达操作系统；短句可以轻量输出，重要场景必须同时给最终话术和表达策略。
- 轻量模式不能省略系统痕迹，至少保留场景判断和表达策略，避免退化成普通润色。
- 场景判断不能随意创造任务名，优先从标准沟通任务中选择，必要时组合两个标准任务。
- 做系统结构设计时，不能只给分类结果；必须先用设计审查框架说明问题空间、模块关系、MECE 检查和适用边界，再用金字塔原理呈现结构。
